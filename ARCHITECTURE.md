# Архитектура и функции Wyre

> Этот файл описывает базовые механизмы авторизации и транспорта.
> Полная и актуальная структура проекта, весь список функций, все 35 коллекций и
> требования к хостингу находятся в **`PROJECT.md`**. При расхождении верным
> считается `PROJECT.md`.

## Стек

- React 19 + Tailwind/Vite — неизменённый интерфейс прототипа.
- Express — HTTPS API и раздача production-сборки; development автоматически
  создаёт локальный сертификат, production принимает PEM или работает за TLS proxy.
- MongoDB native driver — данные и индексы без ORM/облачной платформы;
  development может автоматически поднять persistent embedded MongoDB.
- Socket.IO — push-инвалидация live-запросов без polling.
- Nodemailer SMTP — OTP и magic-link.
- Собственные `httpOnly` cookie-сессии — токен хранится в браузере, в MongoDB
  хранится только его SHA-256-хеш.
- WebRTC — медиа звонков; Socket.IO/MongoDB передают только SDP/ICE-сигналы.

## Авторизация

1. `/api/auth/send-code` проверяет email, временные домены и resend cooldown.
2. Создаёт криптографически случайный шестизначный OTP и magic-link. В БД
   записываются только хеши, срок жизни и число попыток.
3. `/api/auth/verify-code` или `/api/auth/magic-link` атомарно помечает код
   использованным.
4. `wyreUsers.email` уникален. Атомарный upsert находит старый аккаунт или
   создаёт ровно один новый даже при двух одновременных запросах.
5. Создаётся случайная серверная сессия. Cookie имеет `HttpOnly`, `SameSite=Lax`,
   а в production также `Secure`.
6. Существующий профиль получает `pendingChallenge`: пользователь подтверждает
   username и, если задан, телефон. После пяти ошибок все его сессии удаляются.
7. Новый профиль получает `phoneOnboardingPending`: после кода пользователь
   обязательно видит сохранённый экран и выбирает «привязать» или «пропустить»;
   решение переживает refresh и только затем открывается мессенджер.
8. Повторная регистрация на прежний email вызывает вход в прежний аккаунт;
   второй профиль не создаётся.

Yandex OAuth использует state-cookie против CSRF, официальный token/profile API
Яндекса и связывание по подтверждённому email. Все секреты находятся в `.env`.

## Реализованные функции

Полный перечень — в `PROJECT.md`, раздел 5. Кратко реализовано и работает:

- регистрация и вход: email-код, magic-link, Yandex ID, QR, пароль аккаунта,
  дополнительный пароль, TOTP, PIN, WebAuthn, подтверждение нового устройства,
  decoy-режим;
- профиль, аватар, username с историей, телефон, роли, бейджи, предупреждения;
- личные чаты, группы с ролями и топиками, каналы;
- сообщения всех типов, включая вложения, опросы, контакты, live-геолокацию,
  отложенную отправку, самоуничтожение и автоудаление;
- вложения до `MAX_UPLOAD_MB`: потоковая запись на диск, скачивание с HTTP Range,
  просмотр фото и видео прямо в браузере;
- WebRTC-звонки до четырёх человек: signaling, адаптивный битрейт, ICE restart,
  демонстрация экрана, статистика качества, ссылки-приглашения, watch party,
  совместная доска, remote control внутри поверхности Wyre (в приложении для
  Windows — и всей системы по явному согласию), шумоподавление, сворачивание
  звонка в плавающее окно без разрыва связи;
- AI: персональный ассистент Wyre AI с кнопочным согласием, суммаризация,
  семантический поиск, короткие ответы, напоминания, транскрибация, перевод
  текста и голосовых, проверка ссылок, авто-DND;
- приватность: блокировки, гранулярные разрешения, семейная защита, тихая забота;
- модерация: сроковые и постоянные предупреждения с автоснятием, бейджи, роли,
  сроковые и постоянные баны аккаунтов и устройств, разбан, поддержка от имени
  официального аккаунта Wyre и рассылка, журнал;
- официальные сервисные чаты: у каждого пользователя есть чаты «Wyre»
  (поддержка и уведомления) и «Wyre AI» (персональный ассистент);
- уведомления: настройки по чатам, DND, Web Push, системные toast в
  Windows-приложении;
- экспорт JSON/TXT/PDF и ограниченное восстановление личных данных;
- приложение для Windows (`desktop/`, Electron): установщик NSIS с выбором
  папки, трей, автозапуск, офлайн-режим «последнее состояние», журнал,
  remote control уровня ОС через nut-js.

Намеренно не реализовано: секретные E2EE-чаты (отменены продуктовым решением),
групповые звонки более четырёх участников (нужен SFU).

## Модель шифрования

Секретные end-to-end чаты отменены продуктовым решением и не реализуются.
Шифрование в передаче обеспечивает TLS/HTTPS, история хранится на сервере,
поэтому поиск, AI-функции, синхронизация между устройствами, экспорт и
модерация остаются настоящими. Звонки используют DTLS-SRTP внутри WebRTC.
Wyre нигде не описывается как end-to-end encrypted.

## API и realtime

Клиентские методы сохранили контракт `wyre.*`, но транспорт теперь локальный:

- `POST /api/rpc/query` — обычные запросы;
- `POST /api/rpc/mutation` — изменения;
- `POST /api/rpc/call` — совместимость с onboarding state machine;
- Socket.IO событие `wyre:changed` — немедленная инвалидация активных запросов.

Данные в событии не передаются: каждый клиент повторно получает только то, что
ему разрешают membership/auth guards. Polling отсутствует.
