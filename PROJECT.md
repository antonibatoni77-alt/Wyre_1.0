# Wyre: полная структура проекта

Приватный мессенджер для семьи и близких друзей. Интерфейс на русском.

Документ описывает фактическое состояние кода, а не планы. Все числа получены из
исходников: 181 RPC-метод, 37 коллекций MongoDB, 8819 строк серверного кода и
12324 строки клиентского.

Актуальность: 22 августа 2026.

Связанные файлы: `CONFIG_REFERENCE.md` — справочник по `.env`, `DESIGN.md` — UI-контракт,
`AGENTS.md` — правила разработки.

## 1. Что это и как устроено

### 1.1 Технологический стек

| Слой | Технология | Роль |
| --- | --- | --- |
| Клиент | React 19, TypeScript, Tailwind 4, Vite 7 | SPA, собирается в `dist/client` |
| Состояние | TanStack Query 5 | кэш запросов и инвалидация |
| Анимация | motion 12 | переходы интерфейса |
| Сервер | Node.js 20+, Express 5 | HTTPS, RPC, статика |
| База | MongoDB 6 (официальный драйвер) | все данные, без ORM |
| Realtime | Socket.IO 4 | push-инвалидация, без polling |
| Звонки | WebRTC | медиа напрямую между браузерами |
| Почта | Nodemailer | OTP и magic-link |
| Валидация | Zod 4 | схемы всех входных данных |
| Криптография | Node crypto, `@simplewebauthn` | сессии, PIN, пароли, passkeys |
| Push | web-push (VAPID), Firebase (FCM) | фоновые уведомления: браузеры и Android |
| Экспорт | PDFKit | PDF-выгрузка |

Своего фреймворка или облачной платформы нет. Приложение полностью автономно:
Express плюс MongoDB.

### 1.2 Ключевые архитектурные решения

**Сервер — единственный источник истины.** Каждый приватный метод вызывает
`requireVerifiedProfile`, затем проверку членства, приватности и блокировок.
Скрытие элемента в интерфейсе не является защитой.

**Realtime без polling.** Любая мутация в MongoDB эмитит событие `wyre:changed`,
клиент инвалидирует активные запросы и повторно их выполняет. В самом событии
данных нет: при повторном запросе снова работают все guard-проверки.

**Медиа звонков не проходит через сервер.** WebRTC соединяет браузеры напрямую,
сервер передаёт только SDP/ICE. Это главная причина, почему для 20 человек
достаточно скромного хостинга.

**Шифрование: осознанный компромисс.** Секретные end-to-end чаты отменены
продуктовым решением. Транспорт защищён TLS, история хранится на сервере, что
позволяет иметь настоящий поиск, AI-функции, синхронизацию, экспорт и модерацию.
Звонки используют DTLS-SRTP внутри WebRTC. Wyre нигде не называется end-to-end
encrypted.

### 3.3 Планировщик

Один `setInterval` каждые 5 секунд запускает восемь задач:

| Задача | Что делает |
| --- | --- |
| `processScheduledMessages` | отправляет отложенные сообщения, claim атомарный |
| `processDueReminders` | помечает наступившие напоминания |
| `processAutoDnd` | подбирает самые тихие 8 часов по активности |
| `processNotificationJobs` | доставляет web push с повторами |
| `reconcileMissedNotifications` | восстанавливает очередь после сбоя |
| `processQuietCare` | проверяет долгое отсутствие в сети |
| `processExpiredMessages` | удаляет истёкшие сообщения |
| `processExpiredWarnings` | снимает истёкшие сроковые предупреждения |

Планировщик устойчив к падению базы: при потере соединения он один раз пишет
понятное сообщение и приостанавливается, а не заваливает лог стектрейсами.

### 3.4 Модель хранения

`Store<T>` — тонкая обёртка над коллекцией MongoDB. Она создаёт индексы и эмитит
событие изменения, на котором держится realtime. `updateOneSilent` не эмитит
событие: он нужен для служебных касаний вроде `lastSeenAt`, иначе возник бы цикл
инвалидации.

Транзакции не используются. Согласованность обеспечивается атомарными
операторами: `$inc`, `$push`, `$pull`, `arrayFilters` и `findOneAndUpdate` с
фильтром по текущему состоянию. Это осознанное решение: массив `members` больше
нигде не перезаписывается целиком, поэтому одновременные действия двух людей не
затирают друг друга.

## 5. Функции

### 5.1 Авторизация

Реализовано:

- вход по email-коду и magic-link, код одноразовый, с TTL и лимитом попыток;
- ограничение частоты: 10 запросов на email и 30 на IP в час;
- один аккаунт на email через атомарный upsert, повторная регистрация входит в
  существующий аккаунт;
- Yandex OAuth: вход и отдельная аутентифицированная привязка с проверкой email;
- пароль аккаунта: scrypt с версией, минимум 12 символов, 5 попыток и блокировка
  на 15 минут;
- дополнительный пароль как отдельный шаг после входа;
- TOTP, 5 попыток, при исчерпании сессия удаляется;
- PIN из 4 цифр, scrypt, 5 попыток;
- WebAuthn и биометрия: приватный ключ остаётся в системе, сервер хранит только
  публичный;
- подтверждение входа с нового устройства доверенной сессией;
- вход по одноразовому QR;
- decoy-код: отдельный скрытый аккаунт с изолированными данными;
- подтверждение username и телефона после входа;
- сессии в `HttpOnly`, `SameSite=Lax`, в production `Secure`.

Порядок проверок: сессия → аккаунт и устройство не забанены → профиль создан →
username и телефон → TOTP → PIN → доп. пароль → WebAuthn → подтверждение
устройства.

### 5.2 Сообщения

Текст, стикеры, фото, видео, файлы, голосовые, видео-кружки, HTML-вложения,
контакты, геопозиция, live-геолокация, опросы и квизы.

Возможности: ответы, изменение, удаление, пересылка, реакции, закрепление,
избранное, мультивыбор, черновики, упоминания через `@`, точное время прочтения,
самоуничтожение после прочтения, автоудаление через N дней, отложенная отправка
от часа до года, drag-and-drop, передача файла в папку получателя с его согласия,
превью ссылок, sandbox-просмотр HTML, мини-браузер, голосовые цепочки.
Контекстное меню сообщения (правый клик / долгое нажатие) содержит «Расшифровать»
для голосовых и «Перевести на русский» для текста; отправка показывает пузырь
мгновенно и бесшовно подменяет его серверной копией без мерцания.

Ограничения: сообщение до 4000 символов, лента отдаёт последние 500 сообщений,
самоуничтожение до 7 дней.

### 5.3 Вложения

Загрузка идёт по подписанному тикету: сервер выдаёт подпись, файл потоково
пишется во временный каталог и затем перемещается. В памяти файл не буферизуется,
поэтому многогигабайтная передача стоит несколько мегабайт RAM.

Скачивание поддерживает HTTP Range, поэтому видео начинает воспроизводиться сразу
и можно перематывать. Есть режим `download=1` для явного скачивания.

MIME сравнивается по базовому типу, поэтому `audio/webm;codecs=opus` от
`MediaRecorder` принимается корректно.

Лимит на файл задаёт `MAX_UPLOAD_MB`, по умолчанию 50 ГБ. Ссылка на загрузку
живёт 12 часов, на скачивание 6 часов. Пути ограничены каталогами
`private/wyre-chats/`, `private/wyre-stories/` и `private/wyre-avatars/`, выход за
пределы `UPLOAD_DIR` невозможен.

### 5.4 Группы и каналы

Группы: роли владельца, администратора и участника, добавление и удаление людей,
передача владения при выходе, каскадное удаление пустой группы, топики с
отдельными лентами и непрочитанными, опросы, совместный медиа-альбом, фото
группы, автоудаление истории.

Каналы: создание, подписка, посты владельца, комментарии, реакции, просмотры.
Интерфейс канала повторяет чат.

### 5.5 Звонки

Аудио и видео до четырёх участников, mesh-топология без SFU. Звонок не
блокирует мессенджер: кнопка «Свернуть» превращает видеозвонок в плавающее
перетаскиваемое окно, аудиозвонок прячет интерфейс, звук и WebRTC-движок
продолжают работать, а над закреплёнными сообщениями остаётся полоса возврата.

Реализовано: SDP и ICE через сервер, адаптивный битрейт по реальной статистике,
приоритет звука, перезапуск ICE, демонстрация экрана, статистика качества,
одноразовые ссылки-приглашения, шумоподавление через AudioWorklet, включённое
всегда, когда браузер его поддерживает.

Remote control: восьмизначный код участника, явное согласие, статусы
pending → active/declined/ended, постоянный индикатор, мгновенная остановка
любой стороной, защита элементов управления звонком. При старте сеанса цель
автоматически включает демонстрацию экрана, и контроллер видит её полноэкранно
(object-contain), координаты указателя маппятся с учётом letterbox. События
доставляются адресным Socket.IO-каналом комнаты пользователя (движения мыши
коалируются, «последний выигрывает»), запись в MongoDB остаётся резервным
каналом и не создаёт глобальных broadcast-штормов. В браузере управление
работает внутри поверхности Wyre; в приложении для Windows тот же сеанс по
переключателю «Управление ПК» управляет курсором и клавиатурой всей системы
(nut-js, очередь с коалесингом движений, поддержка правой/средней кнопки).
Ограничение Windows: UAC secure desktop не подпускает программный ввод.

Звонок и несколько устройств: звонить (ring) может каждое устройство аккаунта,
но принимает тот, кто первый ответил; экран звонка открывается только на
принявшем устройстве (сервер запоминает deviceId сессии, поле
`joinedByThisDevice` в `wyre.callState`).

### 5.6 AI

Все функции работают через OpenAI-совместимый endpoint и включаются только при
заданных ключах.

Персональный чат «Wyre AI»: у каждого пользователя есть официальный чат с
ассистентом (бейдж Official). При первом входе приходит сообщение с кнопками
согласия на чтение сообщений и голосовых для персонализации — как у ботов в
Telegram. После принятия ассистент учитывает переписку своего чата (голосовые
расшифровываются), профиль, контакты и умеренную выжимку недавних чатов за
30 дней; после отказа работает без персонального контекста. Ответы
генерируются мультитurn-вызовом LLM с защитой от prompt-инъекций, по одному
ответу на сообщение пользователя; без ключа ассистент честно сообщает, что не
настроен (`AI_ASSISTANT_ENABLED`, по умолчанию включён).

Суммаризация пропущенного с отдельным курсором, семантический поиск с серверной
перепроверкой найденных ID, короткие ответы, контекстные напоминания,
транскрибация голосовых, перевод сообщений, генерация изображений по запросу
(бесплатный Pollinations без ключа, `AI_IMAGE_ENABLED`, лимит 12 картинок в
час на пользователя), проверка ссылок на фишинг, автоматический DND по
активности.

Безопасность: контекст ограничен сообщениями чата, участником которого является
вызывающий; текст сообщений передаётся как данные с явной инструкцией не
исполнять инструкции из них; результаты кэшируются в сообщении.

### 5.7 Приватность и безопасность

Двусторонние блокировки, гранулярные разрешения на поиск по номеру, звонки,
приглашения и видимость номера с персональными исключениями, безопасный режим,
фильтр входящего контента, presence-статусы с настройкой видимости.

Семейная защита: связь по одноразовому коду с подтверждением обеих сторон,
взрослый управляет только защитными политиками и не получает доступ к переписке
и геолокации, ребёнок может отозвать связь.

Модерация: предупреждения от 0 до 2 с публичной причиной — постоянные или на
срок (дни/часы/минуты), с автоматическим снятием по истечении и ручным снятием
в админ-панели; бейджи Dev и Official; роли; временные баны на произвольный
срок и постоянные, разбан, блокировка устройства, каскадная блокировка
устройств аккаунта, журнал действий. Права проверяются на сервере при каждом
действии.

Поддержка: у каждого пользователя есть официальный чат «Wyre» (бейдж Official) —
туда приходят приветствие, ответы поддержки и уведомления. Персонал видит
переписку во вкладке «Поддержка» админ-панели, отвечает от имени Wyre и может
отправить одно уведомление всем пользователям сразу (рассылка). Сервисные
аккаунты не находятся поиском, не принимают звонки и не блокируются.

Честное ограничение: идентификация устройства распознаёт профиль браузера.
Очистка данных, приватный режим, другой браузер или переустановка создают новую
запись. Это сигнал против злоупотреблений, а не защита от переустановки.

### 5.8 Уведомления

Настройки по каждому чату: все сообщения, только упоминания, выключено, плюс
временный mute со сроком. Глобальный DND по расписанию и автоматический DND.

Web Push: подписка привязана к сессии и удаляется при её завершении, очередь с
повторами и восстановлением после сбоя, удаление мёртвых подписок по кодам 404 и
410. Решение о доставке принимает только сервер.

### 5.9 Уникальные функции для семьи

Тихая забота: включается самим человеком, порог отсутствия от 1 до 30 дней,
близкие получают мягкое напоминание. Раскрывается только число дней, возвращение
в сеть снимает напоминания.

Альбом памяти: все фото и видео переписки в таймлайне по месяцам, использует уже
сохранённые вложения.

### 5.10 Экспорт и восстановление

Экспорт в JSON, TXT и PDF. JSON версионирован как `wyre-export-v2` и содержит
профиль, настройки, чаты, сообщения, черновики, закладки, напоминания, заметки,
истории, звонки, каналы, блокировки, журнал модерации и манифест вложений.

Секреты не экспортируются: TOTP-шифротекст, соль и хэш PIN, верификатор
дополнительного пароля, decoy-данные, хэши токенов сессий.

Восстановление сознательно ограничено личными сущностями: био, настройки,
черновики, избранное, напоминания, отложенные сообщения, блокировки. Чужая
переписка и параметры безопасности не импортируются, файл с секретами
отвергается. Восстановление идемпотентно.

### 5.11 Что намеренно не реализовано

- Секретные E2EE-чаты — отменены продуктовым решением.
- Групповые звонки более четырёх участников — нужен SFU.
- Горизонтальное масштабирование на несколько процессов — см. раздел 6.7.

### 5.12 Приложение для Windows

Каталог `desktop/` — Electron-оболочка над веб-приложением Wyre (Windows 10/11,
x64). Сборка: `npm run desktop:dist` из корня, результат —
`desktop/dist-app/Wyre-Setup-<версия>.exe` (NSIS, выбор папки установки, ярлыки,
деинсталлятор, иконка Wyre в exe и установщике).

Что внутри:

- окно в стиле Wyre, адрес сервера задаётся в настройках приложения
  (`%APPDATA%/Wyre/config.json`), поддержка самоподписанного сертификата для
  локальной разработки; системное меню Electron отключено полностью — Alt
  больше не открывает панель File/Edit/View;
- системные уведомления Windows через живой Socket.IO (Web Push в Electron
  недоступен): toast при росте непрочитанных в скрытом окне, клик открывает
  чат; входящий звонок в скрытом окне показывает отдельный toast «Входящий
  звонок», клик открывает окно с уже ждущим экраном принятия/сброса;
- офлайн-режим «как в последний раз»: service worker отдаёт последнюю оболочку,
  снимок последних данных (сессия, чаты, открытые переписки) хранится в
  localStorage, экрана «нет соединения» нет — тихая заставка и автоматическое
  переподключение каждые 4 секунды;
- трей, закрытие в трей, фоновый автозапуск с Windows (старт скрытым);
- файловый журнал с ротацией на 7 дней: `%APPDATA%/Wyre/logs`;
- разрешения камеры, микрофона и демонстрации экрана для звонков; демонстрация
  выбирает основной экран без системного диалога;
- remote control уровня ОС в звонке по существующему механизму согласия и кода:
  события указателя и клавиш применяются к системе через nut-js (необязательная
  зависимость; без неё остаётся браузерное управление); движения мыши
  коалируются в очереди («последний выигрывает»), поэтому курсор не отстаёт,
  поддержаны левая/правая/средняя кнопки. UAC secure desktop Windows не
  подпускает программный ввод — честное ограничение.

### 5.13 Приложение для Android (APK)

Каталог `mobile-android/` — нативная WebView-оболочка без единой сторонней
зависимости (одна Activity на чистом android framework API). Сборка:
`npm run android:dist` из корня (или `build.cmd` внутри), результат —
`mobile-android/dist/Wyre-<версия>.apk`, подписанный собственным ключом
`wyre.keystore`. Android 7.0+ (minSdk 24), targetSdk 34, размер ~30 КБ.

Что внутри:

- при первом запуске — экран настроек: адрес сервера, галка «Доверять
  самоподписанному сертификату» (для локальной сети) и галка «Биометрический
  замок приложения»; настройки в SharedPreferences, экран доступен и позже
  через офлайн-экран;
- биометрический замок приложения: при открытии и после минуты в фоне
  оболочка требует подтверждение через системный экран блокировки
  (отпечаток/лицо/PIN — KeyguardManager). WebView не поддерживает WebAuthn,
  поэтому тот же механизм доступен сайту через мост `window.WyreNative`
  (`biometricAvailable` / `authenticate`): после успешного подтверждения веб-часть
  вызывает `wyre.verifyNativeAppUnlock` и сессия считается разблокированной;
- фоновые push-уведомления через Firebase Cloud Messaging: сообщения (кнопки
  «Ответить» с полем ввода и «Прочитано») и звонки (кнопки «Принять» /
  «Отклонить», full-screen intent на заблокированном экране). Кнопки действуют
  через серверные эндпоинты `/api/push-action/*` с одноразовым opaque-токеном
  (`wyre.createPushActionToken`), который веб-часть передаёт в оболочку мостом.
  Работает только при наличии `app/google-services.json`; без него APK
  собирается, а push просто неактивен. Серверная часть — FCM HTTP v1
  (`FIREBASE_*` в `.env`, без Admin SDK);
- офлайн: спокойный экран «Ждём соединение» с кнопками «Повторить» и
  «Настройки», без системной ошибки; плюс офлайн-оболочка «как в последний
  раз» — service worker включён через ServiceWorkerController, а снимок
  последних данных лежит в localStorage (DOM-хранилище включено), как в
  Windows-приложении;
- клик по уведомлению открывает нужный чат (`?chat=<id>`) или экран входящего
  звонка;
- системные разрешения камеры и микрофона запрашиваются при старте и выдаются
  сайту для WebRTC-звонков;
- выбор файлов вложений через системный пикер, скачивание — через системный
  DownloadManager с cookie сессии;
- кнопка «Назад» работает как в браузере внутри мессенджера, двойное нажатие
  закрывает приложение; поворот экрана не перезагружает страницу.

Сборочная среда этой машины использует зеркала: зависимости Gradle — Aliyun
(`settings.gradle`), компоненты SDK ставились через локальный прокси
`android-sdk/mirror-proxy.cjs` с зеркала Tencent (dl.google.com недоступен
из сети); плагин google-services подключён через buildscript-classpath, потому
что plugin-marker через Aliyun не резолвится.

## 6. Хостинг: требования для 10–20 пользователей

Это раздел для подбора сервера. Цифры основаны на фактическом коде: размерах
сборки, лимитах вложений, частоте планировщика и модели realtime.

### 6.1 Профиль нагрузки

Wyre — приватный мессенджер для семьи и близких. Для 10–20 человек нагрузка
принципиально низкая: онлайн одновременно обычно 3–8, пик 20.

| Показатель | Ожидание при 20 пользователях |
| --- | --- |
| Одновременных WebSocket-соединений | до 20–40 (несколько устройств на человека) |
| RPC-запросов в минуту в покое | десятки |
| RPC-запросов при активной переписке | сотни в минуту |
| Планировщик | 1 цикл раз в 5 секунд, 7 задач |
| Пиковый трафик медиа | ограничен `MAX_UPLOAD_MB` и каналом |

Важное свойство: **медиа звонков не идёт через сервер**. WebRTC соединяет
браузеры напрямую, сервер передаёт только SDP/ICE. Это снимает основную
нагрузку, но требует TURN для сложных сетей (раздел 6.6).

### 6.2 Минимальная и рекомендуемая конфигурация

| Ресурс | Минимум | Рекомендуется | Причина |
| --- | --- | --- | --- |
| CPU | 2 vCPU | 4 vCPU | Node в один поток + `mongod`; PDF-экспорт и `scrypt` дают короткие пики |
| RAM | 2 ГБ | 4 ГБ | Node ~150–400 МБ; MongoDB по умолчанию берёт до половины RAM под кэш |
| Диск | 20 ГБ SSD | 100 ГБ+ SSD | База мала, объём определяют вложения |
| Сеть | 100 Мбит | 1 Гбит | Загрузка и раздача вложений |
| ОС | Ubuntu 22.04/24.04 LTS | то же | Node 20+, systemd |

Для 10–20 человек этого достаточно с запасом. Узкое место будет не CPU, а диск
под вложения.

### 6.3 Расчёт диска

Постоянно занято кодом и рантаймом:

| Что | Размер |
| --- | --- |
| `node_modules` | ~240 МБ |
| `dist` (клиент + сервер) | ~2 МБ |
| MongoDB бинарь (только dev) | ~61 МБ |
| База при 20 активных пользователях и истории в год | обычно 0,5–3 ГБ |

Вложения считаются отдельно и растут неограниченно:

```text
диск = 20 ГБ (система, Node, база, запас) + объём вложений + место под бэкапы
```

Ориентиры для 20 человек:

| Активность | Вложений в месяц | Диск на год |
| --- | --- | --- |
| Умеренная: фото, голосовые | 5–15 ГБ | 100–200 ГБ |
| Активная: видео с телефона | 30–80 ГБ | 500 ГБ – 1 ТБ |
| С большими файлами до 50 ГБ | непредсказуемо | считать по факту |

Три вещи, которые обязательно учесть:

1. `MAX_UPLOAD_MB` по умолчанию `51200`, то есть 50 ГБ на один файл. Для 20
   человек это почти наверняка избыточно: один пользователь может занять весь
   диск. Поставьте разумный предел, например `2048` (2 ГБ) или `10240` (10 ГБ).
2. Во время загрузки файл сначала пишется во временный каталог `UPLOAD_DIR/tmp`,
   и только потом перемещается. На пике нужно место под временную копию.
3. Автоудаление сообщений и историй освобождает место, но только если оно
   настроено. По умолчанию история хранится вечно.

### 6.4 Обязательные внешние сервисы

| Сервис | Обязательность | Зачем | Переменные |
| --- | --- | --- | --- |
| MongoDB | обязателен | вся база | `MONGODB_URI`, `MONGODB_DB_NAME` |
| SMTP | обязателен | OTP и magic-link, без него нет входа | `EMAIL_TRANSPORT=smtp`, `SMTP_*`, `EMAIL_FROM` |
| Домен + TLS | обязателен | HTTPS нужен для микрофона и камеры | `SITE_URL`, PEM или `TRUST_PROXY` |
| TURN | практически обязателен | звонки за NAT/мобильным интернетом | `TURN_SERVER_*` |
| Web Push (VAPID) | опционально | фоновые уведомления | `VAPID_*` |
| Yandex OAuth | опционально | вход через Яндекс ID | `YANDEX_CLIENT_*` |
| AI-провайдер | опционально | транскрибация, перевод, суммаризация | `GROQ_API_KEY`, `AI_*` |

Без HTTPS браузер заблокирует `getUserMedia`, то есть звонки не будут работать
нигде, кроме `localhost`. Это ограничение браузера, а не Wyre.

### 6.5 MongoDB: где размещать

`MONGODB_EMBEDDED` поднимает встроенную базу только в development. В production
это запрещено кодом: пустой `MONGODB_URI` вызывает ошибку запуска.

Три рабочих варианта:

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| MongoDB на том же сервере | дешевле, нет сетевой задержки | резервные копии и обновления на вас |
| MongoDB Atlas free/shared | бэкапы и мониторинг из коробки | free-тир ограничен, задержка выше |
| Отдельный сервер БД | изоляция и масштабирование | дороже и сложнее |

Для 10–20 человек проще всего MongoDB рядом на том же сервере плюс регулярный
`mongodump` в отдельное хранилище. Atlas оправдан, если не хотите заниматься
бэкапами вручную.

Транзакции в коде не используются, поэтому replica set не обязателен.

### 6.6 TURN для звонков

Без TURN звонки будут работать в одной домашней сети и часто не будут
соединяться через мобильный интернет и симметричный NAT. Для семьи, где люди в
разных местах, TURN нужен.

Варианты:

- поднять `coturn` на том же или отдельном сервере;
- взять managed TURN.

Трафик TURN считается по релею: примерно 0,5–1,5 Мбит на участника видеозвонка в
каждую сторону. Для четырёх участников это порядка 5–10 Мбит на звонок. Если у
провайдера лимит трафика, это основная статья расхода.

Ограничение продукта: звонки поддерживают максимум **4 участника**
(`MAX_CALL_PARTICIPANTS`), так как используется mesh-топология без SFU. Для 20
пользователей это значит, что общего звонка на всех не будет.

### 6.7 Масштабирование: важное ограничение

Wyre сейчас рассчитан на **один процесс приложения**. Запуск нескольких копий за
балансировщиком сломает две вещи:

1. Socket.IO без общего адаптера: событие `wyre:changed` дойдёт только до
   клиентов своего процесса, у остальных интерфейс перестанет обновляться
   мгновенно.
2. `UPLOAD_DIR` на локальном диске: файл, загруженный на один узел, будет
   недоступен на другом.

Для 10–20 человек это не проблема: один процесс закрывает такую нагрузку с
большим запасом. Горизонтальное масштабирование потребует Redis-адаптера для
Socket.IO и общего хранилища файлов (S3 или сетевой том).

Вертикально масштабировать можно свободно: больше CPU и RAM, быстрее диск.

### 6.8 Порты и сеть

| Порт | Назначение | Доступ |
| --- | --- | --- |
| `PORT` (по умолчанию 3000) | HTTPS/HTTP приложения и WebSocket | наружу или только для reverse proxy |
| 443 | публичный HTTPS, если используется nginx/Caddy | наружу |
| 27017 | MongoDB | только localhost или приватная сеть |
| 3478 / 5349 + UDP-диапазон | TURN, если разворачиваете сами | наружу |

Приложение слушает `0.0.0.0`. Если ставите reverse proxy, закройте порт
приложения от внешнего доступа и включите `TRUST_PROXY=true`, иначе `req.ip`
будет неверным, а он используется для лимита OTP и метаданных сессий.

### 6.9 Два варианта развёртывания

**Вариант A: TLS терминируется в приложении**

Подходит для одного сервера без прокси.

```text
SITE_URL=https://wyre.example.com
HTTPS_KEY_FILE=/etc/letsencrypt/live/wyre.example.com/privkey.pem
HTTPS_CERT_FILE=/etc/letsencrypt/live/wyre.example.com/fullchain.pem
TRUST_PROXY=false
PORT=443
```

**Вариант B: reverse proxy (рекомендую)**

```text
SITE_URL=https://wyre.example.com
HTTPS_KEY_FILE=
HTTPS_CERT_FILE=
TRUST_PROXY=true
PORT=3000
```

Прокси обязан пробрасывать WebSocket (`Upgrade`/`Connection`) и не резать тело
запроса, иначе загрузка больших файлов оборвётся. В nginx для загрузок в
несколько гигабайт нужны `client_max_body_size` под ваш `MAX_UPLOAD_MB` и
увеличенные таймауты.

### 6.10 Проверочный список перед запуском

Обязательное:

- [ ] `NODE_ENV=production`.
- [ ] `SESSION_SECRET` — случайная строка не короче 32 символов, уникальная.
- [ ] `SITE_URL` — реальный `https://` адрес.
- [ ] `MONGODB_URI` задан, база доступна.
- [ ] `EMAIL_TRANSPORT=smtp` и SMTP проверен живым письмом.
- [ ] `OWNER_EMAIL` — ваш email, иначе админ-панели не будет.
- [ ] `MAX_UPLOAD_MB` уменьшен до разумного значения.
- [ ] `UPLOAD_DIR` на постоянном диске и входит в бэкап.
- [ ] TLS работает, проверено на телефоне.

Настоятельно рекомендуется:

- [ ] TURN настроен и звонок между мобильным интернетом и Wi-Fi проверен.
- [ ] `mongodump` по расписанию, восстановление проверено на копии.
- [ ] Бэкап `UPLOAD_DIR`.
- [ ] Мониторинг свободного места: при переполнении MongoDB падает с `WT_PANIC`.
- [ ] Автозапуск через systemd с `Restart=always`.
- [ ] Ротация логов.

Опционально:

- [ ] VAPID-ключи для push.
- [ ] Yandex OAuth.
- [ ] AI-ключи.

### 6.11 Резервное копирование

Нужны обе части, по отдельности они бесполезны:

1. База — только `mongodump`. Копировать каталог `MONGODB_DATA_DIR` у
   работающего сервера нельзя: получится битая база. Это уже проверено на
   практике в этом проекте.
2. `UPLOAD_DIR` — обычная синхронизация файлов.

Экспорт из интерфейса (TXT/JSON/PDF) — это выгрузка данных одного пользователя,
а не резервная копия системы. Восстановление из JSON возвращает только личные
сущности владельца экспорта.

### 6.12 Что произойдёт при 100+ пользователях

Честная оценка, если проект вырастет:

| Порог | Что упрётся | Что делать |
| --- | --- | --- |
| ~50–100 онлайн | один процесс Node, глобальная инвалидация запросов | адресные события вместо `wyre:changed` для всех |
| Рост истории | `listMessages` отдаёт до 500 сообщений и генерирует подписанные URL для каждого вложения | пагинация вместо полной выборки |
| Много узлов | Socket.IO без общего адаптера, локальные файлы | Redis-адаптер, S3 |
| Групповые звонки >4 | mesh-топология WebRTC | SFU, например LiveKit или mediasoup |

Для заявленных 10–20 пользователей ни один из этих порогов не достигается.
